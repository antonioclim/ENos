Why Text Processing?

Linux exposes many resources through file interfaces. Common text-processing inputs include:

  • Configuration files (/etc/*)
  • System and application logs
  • Source code
  • CSV, JSON, XML data
  • Command output
Superpower: grep, sed and awk provide composable tools for filtering and transforming text.

Regular Expressions - Foundation

Regex = a language for describing patterns in text

# Simple pattern - search for the text "error"
error

# Pattern with metacharacters - any line starting with #
^#.*
⚠️ Regex ≠ Globbing!
• Globbing (shell): *.txt = files with the .txt extension
• Regex: .*\.txt$ = a line ending with .txt; file.txt matches, file.txt.bak does not

Basic Metacharacters

Symbol Meaning Example
. Any character (exactly 1) a.c → abc, a1c, aXc
^ Start of line ^Hello → lines starting with Hello
$ End of line end$ → lines ending with end
* 0 or more (preceding) ab*c → ac, abc, abbc
\ Escape special character \. → literal dot

BRE vs ERE - The CRITICAL Difference

GNU grep BRE (default)
  • \+ = 1 or more
  • \? = 0 or 1
  • \{n,m\} = interval
  • \( \) = grouping
ERE (grep -E)
  • + = 1 or more
  • ? = 0 or 1
  • {n,m} = interval
  • ( ) = grouping
🚨 Common mistake: grep 'ab+c' searches literally for "ab+c"!
For one or more: grep -E 'ab+c'; grep 'ab\+c' uses a GNU BRE extension. \? and \| are also GNU extensions, not portable POSIX BRE.

GREP - Global Regular Expression Print

Searches for patterns in files and displays matching lines.

$ grep 'pattern' file.txt
the line containing pattern
Variants:
  • grep - BRE (basic)
  • grep -E - ERE (prefer this to the legacy egrep name)
  • grep -F - fixed strings (prefer this to the legacy fgrep name)
Format:
  • grep [options] pattern file
  • command | grep pattern

GREP - Essential Options

OptionDescription
-iCase insensitive
-vInvert (lines that do NOT match)
-nDisplay line number
-cCount matching lines
-oDisplay ONLY the matched part
-rRecursive in directories
-lDisplay only file names
-A n, -B n, -C nContext: After, Before, Combined

GREP -c: Caution!

$ echo "error error error" | grep -c 'error'
1 ← Counts LINES, not occurrences!
-c counts LINES containing the pattern, not the total number of occurrences!

To count ALL occurrences:

$ echo "error error error" | grep -o 'error' | wc -l
3 ← Correct!

SED - Stream Editor

Edits text in a stream - processes line by line without loading the entire file.

$ sed 's/old/new/' file.txt
... text with "new" instead of "old" ...
💡 Key insight: sed by default writes to stdout, it does NOT modify the original file!

SED - The Substitution Command

s/PATTERN/REPLACEMENT/FLAGS
FlagEffect
gGlobal - all occurrences on a line
iCase insensitive (GNU sed extension)
numberA positive occurrence number, e.g. 2
$ echo "cat cat cat" | sed 's/cat/dog/'
dog cat cat ← Only the first!

$ echo "cat cat cat" | sed 's/cat/dog/g'
dog dog dog ← All of them!

SED - Edit In-Place

🚨 DANGER: sed 's/x/y/' file > file
The shell empties the file BEFORE sed reads it!

Correct solutions:

# With backup (RECOMMENDED)
$ sed -i.bak 's/old/new/g' file.txt

# Without backup (DANGEROUS!)
$ sed -i 's/old/new/g' file.txt

AWK - Structured Processing

With the default newline record separator, AWK treats each line as a record with separate fields.

$ echo "John Smith 30" | awk '{print $1}'
John

$ echo "John Smith 30" | awk '{print $3}'
30
Variables
$0 = the entire line
$1, $2... = fields
$NF = last field
NR = line number
Structure
BEGIN { } - before
{ actions } - per line
END { } - after

AWK - Print With and Without Comma

$ echo "a b" | awk '{print $1 $2}'
ab ← Direct concatenation!

$ echo "a b" | awk '{print $1, $2}'
a b ← With space (OFS)!
⚠️ Very common mistake!
The comma in print inserts the Output Field Separator (default: space).
Without comma = direct concatenation with no separator.

AWK - Unquoted Comma-Delimited Data

# Contract: one record per line, no quoted commas or embedded newlines.
# Use a CSV parser (for example Python csv) when quoting is supported.
# Set separator to comma
$ awk -F',' '{print $2}' employees.csv

# Skip header (NR > 1)
$ awk -F',' 'NR > 1 {print $2}' employees.csv

# Sum of salaries
$ awk -F',' 'NR > 1 {sum += $4} END {print sum}' employees.csv

Pipeline Magic

Combining grep, sed and awk creates powerful solutions:

# Top 5 IPs from log
$ awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5

# Remove full-line # comments and empty lines; preserve order
$ sed '/^#/d; /^$/d' config.txt

# Unique errors with frequency
$ grep -i error log.txt | awk '{print $NF}' | sort | uniq -c | sort -rn

Summary

When to use what?
  • grep = search/filter
  • sed = replace/transform
  • awk = structured processing
Mistakes to avoid
  • Choose BRE, ERE or fixed strings deliberately.
  • sed: first match by default; g when all matches are intended.
  • awk: juxtaposition concatenates; a comma inserts OFS.
  • -c counts lines, not matches
