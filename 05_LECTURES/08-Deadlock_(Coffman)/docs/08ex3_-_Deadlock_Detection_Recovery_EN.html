Recovery Costs

Process termination: Cost = Priority × Resources
Resource preemption: Cost = Rollback time
Total recoveries: 0

Detection Algorithm

  1. Work = Available
  2. Finish[i] = (Allocation[i] == 0)
  3. find i: Finish[i]=false and Request[i] ≤ Work
  4. Work = Work + Allocation[i], Finish[i] = true
  5. Repeat until no further process can complete
  6. An unfinished process holding resources belongs to the detected deadlocked set

Process Termination

Option 1: Terminate all deadlocked processes
  • Releases all their model resources; real recovery also requires resource consistency
  • Loses every terminated process’s unsaved progress
Option 2: Terminate one at a time
  • Terminate one process, then check for deadlock again
  • More complex, but potentially less recovery cost
  • Criteria: priority, held resources and execution time

Resource Preemption

Victim Selection

Choose a victim using an explicit criterion such as recovery cost, priority or waiting time.

Rollback

Restore the victim to a consistent checkpoint when supported; otherwise termination may be required. Some resources cannot safely be preempted.

Starvation Prevention

Account for previous rollbacks when selecting victims so the policy does not repeatedly penalise the same process.
