The Safety Algorithm

  1. Initialise: Work = Available, Finish[i] = false
  2. find i: Finish[i] = false and Need[i] ≤ Work
  3. Simulate: Work = Work + Allocation[i], Finish[i] = true
  4. Repeat: Until no further unfinished process can complete
  5. Check: If every Finish[i] is true → SAFE

Key Formulae

Need = Max - Allocation
Candidate Completion Condition: Need[i] ≤ Work
After simulated completion: Work += Alloc[i]

Understanding the Banker’s Algorithm

Bank Analogy

The bank (OS) has limited funds (resources). Customers (processes) declare credit limits (Max). Before granting a request, the bank checks that some completion order can meet all declared maxima.

  • Available: Funds in the vault
  • Max: Credit limit
  • Allocation: Funds currently lent
  • Need: The customer’s remaining maximum claim

Safe vs Unsafe State

SAFE State: At least one order allows every process to complete within its declared maximum claim.
UNSAFE State: No safe completion sequence exists. This does not by itself mean the system is already deadlocked.
