Limits and toy OOM policy

The unified cgroup v2 example assumes an owned delegated hierarchy, enabled parent controllers and an attached workload. CPU quota and I/O ceilings are not reservations. The model represents one process and deliberately omits reclaim: crossing memory.max immediately ends that toy process. Real reclaim, OOM selection and memory.oom.group affect native behaviour. Start after OOM explicitly resets the process and its counters. Memory units here use 1024² bytes.

What are Control Groups (cgroups)?

Cgroups account for and can limit resources such as CPU, memory and I/O for groups of processes. Configured controllers constrain the covered resources; cgroups alone do not provide every isolation or security property.
