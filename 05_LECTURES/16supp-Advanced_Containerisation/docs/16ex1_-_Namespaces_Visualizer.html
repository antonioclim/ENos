Configured namespace scenario

These controls change a conceptual view and transcript; they create no native namespaces. USER on explicitly assumes UID 0 is mapped to host UID 100000; ordinary docker run alone does not establish that mapping. MNT on assumes a separately prepared root filesystem as well as mount isolation. TIME models a monotonic/boottime offset, not a private wall clock. All off views share their corresponding host namespace. Privilege and security also depend on capabilities, mounts, devices, seccomp and the shared kernel.

What are Namespaces?

Namespaces scope views of particular operating-system resources. A process sees resources visible through that namespace rather than every host/container view. They provide part of container isolation in Linux.

PID NET MNT UTS IPC USER CGROUP TIME

PID

Process IDs

Scopes process IDs; this configured container has its own visible PID 1.

NET

Network Stack

Scopes network interfaces, addresses, routes and related network state.

MNT

Filesystem

Scopes mount visibility; a separate root filesystem also requires explicit setup.

UTS

Hostname

Scopes hostname and NIS domain name.

IPC

IPC Objects

Scopes System V IPC and POSIX message queues, not every IPC mechanism.

USER

User/Group IDs

Provides configured UID/GID mappings; this example maps container UID 0 to host UID 100000.

CGROUP

Control Groups

Scopes the visible cgroup hierarchy root.

TIME

System Clock

Supports configured monotonic/boottime offsets (Linux 5.6+), not a private wall clock.
