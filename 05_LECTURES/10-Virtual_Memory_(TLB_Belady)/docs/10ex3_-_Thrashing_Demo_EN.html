These are illustrative stochastic curves, not measured operating-system results. A simulation step represents 0.5 seconds; fault rate is faults per simulated second. Presets rebuild every process and use the selected size as its working set: normal 4×40/256, near-thrashing 8×40/256 and thrashing 15×40/256. The model uses a 1.5 working-set/RAM threshold for the thrashing warning; real behaviour depends on workload and paging policy.

What is Thrashing?

Thrashing occurs when excessive paging dominates useful process execution.

Causes: Too many active processes, insufficient memory or poor locality
Responses: Reduce active multiprogramming, add memory or use working-set allocation

Reducing Thrashing

Working Set Model: Allocate frames for each process’s current working set
Page Fault Frequency: Monitor each process’s page-fault rate
Load Control: Suspend selected processes when memory demand exceeds capacity
