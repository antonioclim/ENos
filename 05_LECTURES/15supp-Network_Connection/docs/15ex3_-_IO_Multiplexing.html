Lecture 15 • select() vs poll() vs epoll()

Illustrative cost model

The chart and cards use select=2N, poll=1.9N and epoll=5+3R cost units, where N is watched connections and R is ready connections. These constants are instructional inputs without measured provenance. The chart holds the currently selected ready fraction fixed. For the select example, descriptors are assumed consecutive from 3, so the largest is N+2 and must be below the common Linux/glibc FD_SETSIZE=1024. This is a descriptor-value bound, not a universal connection-count limit. Real costs depend on workload, changes to the interest set and returned events.

The Problem: A Server with Multiple Connections

How can one thread handle many connections without blocking on one idle connection?

Blocking I/O (WRONG) 
while (true) {
    data = recv(client1);  // Blocked here
    // Cannot serve client2, client3... in this blocking sequence
    // until client1 provides data or the call completes for another reason
}
I/O Multiplexing (CORRECT) 
while (true) {
    ready = wait_for_any(clients);
    for (fd in ready) {
        handle(fd);  // only the ready descriptors
    }
}

O(n) scan

An fd_set represents a descriptor set; in this bitmap illustration each bit corresponds to a file descriptor:

C Code — select()
fd_set readfds;
FD_ZERO(&readfds);
FD_SET(fd1, &readfds);  // Set the bit for fd1
FD_SET(fd2, &readfds);
FD_SET(fd3, &readfds);

select(maxfd+1, &readfds, NULL, NULL, timeout);

// after select, inspect the returned descriptor sets
if (FD_ISSET(fd1, &readfds)) handle(fd1);
if (FD_ISSET(fd2, &readfds)) handle(fd2);
// ... check every descriptor

Disadvantages:

  • • FD_SETSIZE Limit (1024)
  • • Scans the supplied descriptor range in this model
  • • fd_set is modified; rebuild or copy it before the next call
  • • Passes the descriptor sets again on each call

Advantages:

  • • Portable (POSIX standard)
  • • Simple interface for small descriptor sets
  • • Widely available on POSIX platforms

poll() - Array of Structs

O(n) scan

Each pollfd array entry contains a descriptor, requested events and returned events:

Index fd events revents Status
C Code — poll()
struct pollfd fds[MAX_CLIENTS];
fds[0].fd = fd1; fds[0].events = POLLIN;
fds[1].fd = fd2; fds[1].events = POLLIN;
fds[2].fd = fd3; fds[2].events = POLLIN;

int n = poll(fds, nfds, timeout);

// after poll, check revents
for (int i = 0; i < nfds; i++) {
    if (fds[i].revents & POLLIN) {
        handle(fds[i].fd);
    }
}

Advantages Relative to select():

  • • Not constrained by the fd_set FD_SETSIZE bound
  • • The input descriptors/events can be reused; revents is refreshed by poll()
  • • events/revents separate
  • • An array-based API

Still problematic:

  • • Still scans the supplied array
  • • Copies array on each call
  • • Large arrays can be costly; practical capacity needs workload measurements

C Code — epoll()
int epfd = epoll_create1(0);

struct epoll_event ev;
ev.events = EPOLLIN;
ev.data.fd = fd1;
epoll_ctl(epfd, EPOLL_CTL_ADD, fd1, &ev);
// ... add more fds (one-time setup!)

struct epoll_event events[MAX_EVENTS];
int n = epoll_wait(epfd, events, MAX_EVENTS, timeout);

// events[] contains the returned ready events
for (int i = 0; i < n; i++) {
    handle(events[i].data.fd);  // Direct access!
}

Why Can epoll Help with Large Interest Sets?

1. Ready-Event Delivery

Retrieve ready events instead of submitting the whole interest set on every wait

2. Kernel-side storage

The interest set is retained in the kernel; returned events still cross the interface

3. Edge/Level trigger

Explicit level-triggered or edge-triggered notification semantics

The C10K Problem

How can a server handle 10,000 or more simultaneous connections?

select()

The illustrated glibc fd_set interface has FD_SETSIZE=1024. Use poll/epoll for larger descriptor values rather than assuming a recompilation is a portable fix.

At 10K: outside this fd_set descriptor range

poll()

The call examines the supplied 10,000-entry array each time; measured cost depends on the workload and implementation.

At 10K: full-array scan cost

epoll()

Returns ready events from a persistent interest set. Practical capacity depends on memory, workload and the full server design.

At 10K: avoids resubmitting the full interest set
