Mutex (Sleep) Spinlock (Busy)

Which lock and execution context?

An uncontended futex-backed mutex often stays in userspace; a contended wait can block in the kernel. A user-space spinlock is distinct from an IRQ-safe kernel spinlock. Kernel interrupt contexts cannot use sleeping locks, and the correct IRQ/preemption variant depends on context. A single CPU does not by itself make all spinlocks deadlock: owner scheduling and interrupt/preemption constraints matter. The numeric comparison is a declared serial-critical-section toy workload, not measured lock performance.

When to Use?

Consider a Mutex When:

  • The critical section is long (I/O or substantial work)
  • The system has few cores or a single core
  • Many threads contend for the same lock (high contention)
  • Reducing wasted CPU/energy is important

Consider a Suitable Spinlock When:

  • The critical section is very short (a few bounded operations)
  • The system has multiple cores
  • The lock is used in an appropriate interrupt handler
  • When sleeping is forbidden in the particular context, such as an atomic kernel section
