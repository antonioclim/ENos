Sequential walkthroughs and fixed instructional costs

The two animations are sequential walkthroughs, so their visual finish order is not a race. The 1400 versus 280 cycle inputs have no established empirical provenance and do not support a typical speed claim. The process path assumes an untagged address-space switch; the user-level cooperative path remains on the same kernel thread, uses integer-only work and makes no floating-point-state change. Its zero FPU/kernel-stack entries apply only to those assumptions. Native kernel-scheduled threads need their own CPU/FPU context and kernel execution state. PCID/ASID can avoid a full TLB flush, and cache effects depend on working sets.

Why Can a User-level Switch Cost Less?

Process Switch — Sources of Cost

  • TLB handling is architecture-dependent: this example charges a flush on an untagged model. PCID/ASID-tagged translations can survive an address-space switch.
  • Cache cold — the new task’s working set may not be cached
  • Page Table Base Register — changes when switching address spaces in this model
  • Kernel structures: save/restore the relevant execution state; the whole PCB is not swapped.

User-level Switch — Potential Savings

  • Same address space — no address-space change in this model
  • Cache warm — shared data may already be cached; locality must be measured
  • Declared cooperative model: switch within one kernel thread, preserving ABI-required registers and stack. Native OS threads also have independent CPU/FPU and kernel execution state.
  • Runtime TCB — runtime bookkeeping differs from a kernel task record; size is implementation-dependent
