                    Summary: Zombie Process
                

                

                    

                        Definition: A process that has exited but whose status has not yet been collected with wait().
                    

                    

                        System state: Retains exit status and kernel process metadata, but does not execute or retain its user address space.
                    

                    

                        Risk: Too many zombies can exhaust configured process limits; 32,000 is an illustrative limit, not a universal default.
                    

                    

                        solution: The parent or designated reaper must collect the status with wait()/waitpid(), unless an appropriate automatic-reaping policy applies.
                    

                

            


            

                

                    👤
                    Summary: Orphan Process
                

                

                    

                        Definition: A process whose parent exits before it does.
                    

                    

                        Reparenting: In this selected model, init (PID 1) becomes its parent; Linux can also use a living child subreaper.
                    

                    

                        Benefit: The selected init reaper promptly collects the adopted child’s exit status, avoiding a persistent zombie.
                    

                    

                        Daemon pattern: Traditional daemonisation may deliberately orphan a child; service-manager supervision uses other lifecycle arrangements.
