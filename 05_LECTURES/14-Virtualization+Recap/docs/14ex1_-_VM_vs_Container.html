Virtual Machines vs Containers

Architectural comparison and use cases

Configuration and measurement limits

The displayed times, memory and throughput are fixed instructional inputs with no established measured provenance. A VM exposes virtual hardware under a particular hypervisor and supported guest architecture; a container shares its host kernel. Neither has an unconditional security guarantee. User namespaces, capabilities, mounts, devices and runtime policy determine container privileges; root in a container is not automatically unprivileged on the host. Whether to retain fully specified hypothetical numbers or replace them with a reproducible benchmark remains an author decision.

When Should Each Be Considered?

VM Ideal
  • • Different guest operating systems, where supported
  • • Separate guest kernel required; isolation depends on configuration
  • • Legacy applications
  • • Full system testing
  • • Security-critical workloads
VM Security
  • • Multi-tenant hosting
  • • Untrusted code: requires a specified threat model and hardened boundary
  • • Kernel-level isolation
  • • Compliance requirements
  • • Hardware-level separation
Container Ideal
  • • Microservice architectures
  • • CI/CD pipelines
  • • Fast scaling
  • • Development environments
  • • Cloud-native apps
Container DevOps
  • • Fast iteration
  • • Kubernetes orchestration
  • • Resource efficiency
  • • Portable applications
  • • 12-factor apps

VM Technologies

Type 1 Hypervisor (Bare Metal)

Runs directly on hardware. Ex: VMware ESXi, Hyper-V, Xen

Type 2 Hypervisor (Hosted)

Runs on a host OS. Ex: VirtualBox, VMware Workstation

Hardware Virtualization

Intel VT-x, AMD-V - CPU support for efficient virtualisation

Container Technologies

Namespaces

Isolates: PID, Network, Mount, User, IPC, UTS

cgroups (Control Groups)

Controllers cover CPU, memory and I/O; network policy may require additional mechanisms

Union Filesystems

Overlay layers for efficient images (OverlayFS, AUFS)

Hybrid Approach: Best of Both Worlds

Containers in VMs

Runs containers in a VM for additional isolation. Common in cloud (EC2 + Docker).

Kata Containers

Lightweight VMs that run containers. The boundary and performance depend on the guest, runtime and configuration.

Firecracker

Firecracker is a microVM technology. The displayed ~125 ms startup figure is an unverified illustrative input here, not a timing guarantee for this lab.
